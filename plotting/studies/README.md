# plotting/studies

Documented, command-line versions of the analysis notebooks in `plotting/`. Each script has a module
docstring (what it makes, which inputs it reads, which technote figures it feeds), a `main()` and
`--help`. Shared paths, versions and figure helpers live in `common.py`; style rules are in
`CONVENTIONS.md` (mutools style, ruff E/F/I/B/UP at line length 100).

Run with the mutools environment from the repository root:

```
/Users/mueller/Projects/mutools/.venv/bin/python plotting/studies/<script>.py --help
```

| `signal_selection.py` | `signal.ipynb`, efficiency cells of `notebook.ipynb` | signal/selected histograms, efficiency and purity |
| `resolution.py` | `resolution.ipynb` | resolution stacks and overlays |

## Figure provenance (prototype)

`provenance.record()` writes `<figure>.prov.json` next to a figure so that it can be remade from the sidecar alone:

* the figure's hash; the producing script (path, hash, git commit), the command line and the arguments that select the figure;
* every input file (size, mtime and, if under 64 MB, a hash);
* for inputs that are PROfit outputs (`<tag>_v1_PROplot*.root`, `<tag>_v1_surf.root`; found from the file name): the ini with
  that `tag` (full text), the XML it names (hash, git commit, and the content itself when it is not committed), the
  `work/<key>.root` files the XML reads resolved to real paths, the cache files, the PROfit version (from the logs) and the run
  commands noted in the ini header.

Hooked: every figure script in this directory (`exposure.py` makes no figures). Scripts either
call `provenance.record()` where a figure is moved into place (`systematics`, the `data_access` panels, `surface`, the efficiency and
resolution plots) or call `common.set_provenance(__file__, inputs)` once so that `common.save_figure` records every figure
(`dent_study`, `sbnd_scan`, `conditional_constraint`, `detvar_*`, `dent_cathode_break`, `data_access_phases`). A directory among the
inputs is tracked by file count, total size and newest mtime. The PROfit recipe is picked up automatically from any input whose file
name starts with a known ini `tag` (`<tag>_<output tag>_PROplot*.root` or `_surf.root`); where several inis share a tag the output tag
chooses (`..._cvrw_phase2_...` selects the `phase2` ini). Figures that read many PROfit files (the p-value summaries) pass
`recipe=False` and refer to their per-panel sidecars.

```
python scripts/figure_provenance.py list    figures/provenance_demo
python scripts/figure_provenance.py check   figures/provenance_demo --technote ../spineosc_technote
python scripts/figure_provenance.py coverage docs figures --technote ../spineosc_technote   # technote figures with and without provenance
python scripts/figure_provenance.py show    figures/provenance_demo/sensitivity_baseline.pdf.prov.json   # the steps that remake it
python scripts/figure_provenance.py restore figures/provenance_demo/sensitivity_baseline.pdf.prov.json DIR   # writes the recorded ini and XML
```

`check` reports OK, STALE (the script, ini, XML or an input changed, or a cache is older than the ini or XML), MODIFIED (the figure
file was replaced or edited) or MISSING, and exits non-zero otherwise; `--technote` also says whether the technote's copy is the
recorded one. `common.configure_style` fixes `SOURCE_DATE_EPOCH`, so identical inputs give byte-identical PDFs.

Manifest link (`xml/MANIFEST.toml`): each recorded ini and XML carries its manifest family (pattern, status, purpose, consumer, technote section,
regenerate command, reviewed). `check` then flags a figure as STALE when its XML's family is now `archived` or `deprecated` (naming
`superseded_by`), and adds a note when the figure's script is not the family's `consumer` or the family's status changed since the figure was
made; `show` adds the family's `regenerate` command. `scripts/figure_provenance.py manifest <dirs> --technote ...` lists every family with its
status, its technote section (the `figures/<section>` folder is counted), the figures with provenance that come from it and whether they are OK.
`scripts/xml_manifest.py --check` now also requires each family's `consumer` to exist.

Not recorded: the PROfit binary itself (only the version string, when a log exists), the cache contents (PROfit's cache key covers
the XML but not the ini flags, so the checker compares modification times), and how the `work/` inputs were made upstream
(for example the `cvrw` files from `reweight/`).
